# Airport Shift — 설계 원칙과 데이터 형식 (Claude·GPT 공용, 2026-10-09)

> 이 문서는 GitHub에 올라가지만 공개 사이트에는 나오지 않습니다(`_build/` 아래).
> GPT는 이 형식으로 미션·사건을 쓰고, Claude는 이 형식을 읽는 엔진과 화면을 만듭니다.

## 1. 목표
- 최종 목표는 GPT 원안 그대로입니다. 여객운송·탑재관리·운항관리·지상조업·화물·비정상 운항·정비·지점 운영을 **하나의 항공편**으로 잇는 항공 커리어 시뮬레이션 RPG입니다.
- 만드는 순서는 **모듈 단위**입니다. 첫 모듈은 체크인이고, 이것이 재미있다고 확인된 뒤 다음 모듈을 붙입니다.
- 체크인 시제품도 처음부터 **공통 항공편 엔진** 위에서 만듭니다. 나중에 모듈을 붙일 때 다시 만들지 않기 위해서입니다.

## 2. 지키는 원칙
1. **필수 조건은 거래 대상이 아닙니다.** 안전·보안·여행 서류·탑재 제한은 선택지로 어길 수 없습니다. 어기려는 행동은 막고 「왜 안 되는지」를 짧게 보여 줍니다.
2. **고민은 적법한 방법들 사이에서 합니다.** 시간·비용·승객 만족·직원 부담·다음 사건에 대한 영향을 비교하게 만듭니다.
3. **판단이 다음 장면을 바꿉니다.** 점수만 바뀌어서는 안 되고, 인원·시간·대기열·짐·승객 상태가 바뀌어 다음 사건에 영향을 줍니다.
4. **직접 조작이 있습니다.** 여권과 예약 대조, 짐 무게 확인, 좌석 배정, 탑재 배치처럼 손으로 하는 일이 중심이고, 객관식은 보조입니다.
5. **끝나면 리플레이가 있습니다.** 근무가 끝나면 판단 순서·결과·더 나았을 선택·관련 레슨 링크를 보여 줍니다.
6. **무료로도 완결된 경험을 줍니다.** 체크인 기본 미션 3개로 첫 항공편을 출발시키는 데까지는 무료입니다. 중간에 끊어 결제를 요구하거나 실패를 유도하지 않습니다.
7. **모든 데이터는 가상**입니다. 실제 회사명·양식 번호·개인 정보를 쓰지 않습니다.
8. **3개 국어**로 씁니다. 승객 대사는 회화 연습 도구와 같은 품질 기준(자연스러운 일본어 우선)을 따릅니다.

## 3. 항공편 상태(엔진이 들고 있는 값)
```
flight: { id:'ACN1027', from:'NRT', to:'ICN', std:'10:30', type:'B737-800', seats:189,
          weather:'snow'|'clear'|..., booked:176 }
clock:  { now:'08:45', toClose:'09:50' }                // 카운터 마감까지
staff:  { counter:2, support:1, supervisor:1 }          // 지금 쓸 수 있는 사람
queue:  { waiting:14, avgWait:6 }                        // 줄
pax:    { checked:92, special:[...], mood:0..100 }       // 승객 만족
bags:   { count:110, kg:2150, heavy:3, irregular:[] }
flags:  { docsIssue:false, groupLate:false, ... }        // 사건끼리 주고받는 표시
log:    [ ... ]                                          // 리플레이용 판단 기록
```

## 4. 사건 카드 형식 (GPT가 쓰는 부분)
```
{ id:'ci-name-mismatch-1', module:'checkin', lv:2,
  title:{ja,ko,en},
  when:{ phase:'checkin', minToClose:[20,60], requires:{ flags:{} } },   // 나올 수 있는 조건
  scene:{ja,ko,en},                       // 상황 설명 1~2문장
  pax:{ name:'가상 이름', lang:'ko', mood:60 },
  must:[ {ja,ko,en} ],                     // 반드시 지켜야 하는 것(선택지가 아님)
  options:[
    { id:'self', label:{ja,ko,en},
      effects:{ time:+4, queue:+5, mood:-5, staff:{} },               // 상태 변화
      next:['ci-group-bags-1'],            // 이어서 나올 수 있는 사건(조건이 맞을 때)
      why:{ja,ko,en} },                    // 리플레이에서 보여 줄 설명
    { id:'support', ... effects:{ time:+1, staff:{ support:-1 } }, next:['ci-group-bags-1'] },
    { id:'supervisor', ... }
  ],
  lessons:['gnd/1-5'],                     // 관련 레슨(강좌 코드/레슨 번호)
  src:[{ url:'', checked:'2026-10-09' }]   // 규정 관련 내용의 출처
}
```
- 선택지는 2~4개, **모두 적법**해야 합니다. 차이는 effects와 next로 만듭니다.
- 같은 사건이라도 상태(인원·시간)에 따라 가장 좋은 선택이 달라지게 effects 값을 정합니다.
- `next`에 쓰는 id는 같은 묶음 안에 있어야 합니다.

## 5. GPT에게 처음 부탁할 것
- 312개 소재 중에서 체크인 모듈에 맞는 사건 **8~10개**를 골라 위 형식으로 작성합니다.
- 서로 이어지는 묶음 2개로 나눕니다. 예: 서류 문제 → 단체 짐 문제 → 마감 직전 늦은 승객.
- 파일 하나(`as_checkin_batch01.js`, `window.AS_EVENTS=(window.AS_EVENTS||[]).concat([...])`)와 출처 목록을 함께 주세요.
