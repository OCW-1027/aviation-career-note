# AIP 관리 절차 (T-36, 2026-11-12)

사이트에서 AIP(항공로지)를 근거로 쓴 문장을 목록으로 관리하고, AIP가 바뀔 때마다 그 문장만 다시 확인합니다.

## 파일
- `_build/aip_refs.json` — AIP 근거 문장 목록(ID·강좌·레슨·원고 파일·문장 일부·AIP 장절·확인한 판)
- `_build/aip_refs.mjs` — 목록 점검과 수정 의뢰 초안 만들기
- 빌드할 때 「AIP 근거 문장이 원고에서 사라졌는지」를 자동으로 알려 줌(빌드는 멈추지 않음)

## AIRAC(28일)마다 할 일
1. 새 일본 AIP를 PC `7. 사업개발\참고자료\AIP File Download Service\`에 넣는다(사용자). AIXM zip은 쓰지 않는다.
2. `6_OTHER\Japan_Key_Changes` PDF에서 바뀐 공항(RJAA 등)·장절(AD 2.20, ENR 1.7 등)을 본다.
3. `node _build/aip_refs.mjs --match "RJAA,AD 2.20,ENR 1.7" --out 결과.md` → 해당 문장만 표로 나온다.
4. 표의 문장을 새 AIP와 맞춰 본다. 다르면 일·한·영 원고와 그림(figs_gnd.js 공항 카드 등)을 함께 고치고, `aip_refs.json`의 `anchor`(문장 일부)와 `checked`(확인한 AIP 유효일)를 새로 적는다.
5. 바뀐 것이 없어도 `checked`는 그대로 둔다(그 판에서 바뀌지 않았다는 뜻).

## 원칙
- AIP에만 있는 값(운용 시간, 활주로 길이, 발착 횟수, APU 제한, CIQ 시간, 전이고도 등)을 문장에 쓰면 목록에 한 줄 추가한다.
- 나라의 발착 방침(예: 이타미 제트기 200회)이나 공항회사 발표(예: 나리타 0시 30분 탄력 운용)는 AIP가 아니므로 `note`에 출처를 적는다.
- 한국 AIP는 내려받기가 안 되므로 KOCA eAIP 공개 페이지로 확인하고 `checked`에 `KR 판 날짜`를 적는다(인천은 아직 미확인).
- 공개 전에 한 번 전체를 다시 대조한다(T-36 ②).
